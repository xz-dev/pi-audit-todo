## Context

`index.ts` combines rpiv-todo's board with the maintenance entrypoint. Both ordinary tool calls and audit commits use `commitTodo`, the same reducer and persistence lane, and the existing `rpiv-todo-state` snapshots. The child only supplies structured proposals. The original JEV repository is a frozen migration source, not a runtime or package dependency. Stock Pi 1.5.2 is the tested target; the private runtime uses the same fork mechanism as Reflect.

Reflect's `src/extension.ts` calls `pi-extension-utils/private-inquiry` with a private runtime. Continue's `src/activity-grace.ts` qualifies aggregate idle with a *10-second* fence; `LEGACY_MAX_WAIT_SECONDS` in its `src/commands.ts` is only a historical renderer limit. Reuse activity observations, **not** the fence, locks, elapsed idle time, or that legacy constant. This design measures ordinary working intervals itself. See `proposal.md` for scope.

## Goals / Non-Goals

- Make the actual board, revision, due reason, write outcome and original session identifiable for each review. No global task IDs.
- Keep ordinary main work independent of review scheduling and child execution. Only the parent side owns mutations; multiple reflections must not implicitly serialize the main agent.
- Do not implement another task store, impose a hard WIP limit, infer task completion from elapsed time, compel trivial initialization, execute a proposed next step, or feed private reasoning back into the parent prompt.

## Decisions

1. **Use a branch-local board reader and two independent counters.** Normalize direct successful TODO results and native rpiv mutation snapshots into canonical task revisions, deduplicating the same mutation reported twice. At ordinary `turn_end`, compare the previous settled set of `in_progress` IDs with the final one. With final count ≥2, dispatch one private review per new ID, even on a same-size swap; require concrete evidence for keeping the whole set active. Ignore intermediate toggles. Rehydrate the previous baseline; an unchanged board with two active items at reload is not a new activation.
2. **Measure observed work, not age on a wall clock.** Use monotonic time and the union of known ordinary busy attachments for the owned root (main and participating child sessions). Overlap counts once; exclude maintenance/private inquiry activity, all-idle periods, outages and process downtime. Record durable branch-local accrued work at lifecycle/accounting boundaries without adding model messages. A boundary or deadline during active work can make an item due without a new main loop; switching to all-idle settles the preceding interval and disarms the running deadline. Never create activity solely to advance a clock. On restart resume from the last durably known total. If migrating an item without a reconstructible time origin, start time at first observation rather than inventing elapsed work.
3. **Schedule by item revision.** Keep the last real mutation, last accepted review (including an evidence-backed keep), and a terminal-review marker separately. Use the later baseline in each counter; compare strictly `>30` loops or `>1,800,000` ms. Persist keys against branch ancestry and task revision. A due-by-both item has one maintenance obligation; parallel triggers remain one distinct fork per new active item. An already outstanding fork can satisfy a coincident maintenance obligation only if it actually covers that exact item/revision with an accepted decision. Unrelated updates, failed/no-op writes, retries and mere list calls do not buy time. Compare-and-record receipts; avoid hot retry or fork-on-fork loops.
4. **Reuse private inquiry, not another extension's lifecycle.** Capture parent session, branch anchor, user boundary, model/thinking, board and relevant evidence. Limit child capabilities to bounded read-only inspection and its designated result; no shell, delegation, parent TODO calls or public continuation. Each attempt returns typed item decisions (expected version, reason/evidence and either KEEP or a concrete allowlisted TODO mutation). Treat its natural-language advice as untrusted input, not a command. The threshold fork must account for the *whole* active set, not justify only its triggering ID. Forbid speculative completion/deletion; ambiguous evidence goes into a concrete keep reason. Do not copy Reflect's automatic continuation behavior.
5. **Write through the board owner's supported mutation path.** Parent consumes results in a single commit lane for that board, never by replaying fabricated tool messages, editing session JSONL, mutating the child's slot or maintaining a second TODO list. Bind target by parent session and branch; immediately before each write re-read the task, relied-on dependencies and (for parallel findings) active cohort. Accept unrelated changes; reject changed preconditions, invalid transitions, user takeover and retired branch work. Foreign `#7` is not this board's `#7`. An ordinary `ExtensionContext` is not a tool-execution context: do not assume event callbacks have `ctx.executeTool`. First prove a supported parent-session operation against the target Pi/rpiv versions, including serialization with ordinary writes and post-write readback. If the installed API lacks that seam, fail closed and report the integration prerequisite; do not ship a counterfeit board or silently ask the main model to execute writes. Any required external API change is separate scope.
6. **Publish facts after commit.** Store a receipt with parent revision and idempotency key. Derive one compact context message from actual results: changed fields and reason, specific keeps, conflicts or failures as applicable. If some operations succeed before another is rejected, report exactly those successes and rejections. Never retry an operation of uncertain outcome without checking the authoritative board. No hidden transcript, synthetic user approval, forced turn, continuation or execution of planned steps.
7. **Isolate rather than install.** Prefer a public side-effect-free runtime/activity primitive with pinned compatible versions; a private Continue component is allowed when it meets that contract. Never import its extension initializer or share mutable singletons by default. Give this extension its own ownership/child correlation, activity namespace, timers, receipt types, cancellation handles and disposal. Use private child classification/exclusion supported by the runtime; avoid assuming a new namespace alone makes a busy child invisible to Continue. Verify actual co-installation in both load orders, including independent cancellation. Do not require any public `pi-subagents`, Reflect, Continue or JEV commands. The present audit uses Pi dev dependency `^0.85.1` whereas the inspected Reflect runtime requires Pi `>=1.3.0`; select and document a tested minimum supporting *both* fork and parent writeback, not an assumed drop-in upgrade.

## Risks / Trade-offs

- **Stale model interpretation changes scope** → Only board bookkeeping backed by the parent's evidence is permitted. Re-check referenced facts/versions; never turn uncertainty into completion, cancellation, or user approval.
- **Fork volume or crashes** → Distinct logical forks for distinct activations, no repeats for unchanged sets, coalesce duplicate maintenance signals, suppress duplicate writes/receipts, disclose failures. Bounded execution capacity may queue work but cannot merge or drop distinct activations silently.
- **Unobservable work** → Account only for observed participating sessions. Never guess downtime or treat a stalled/dead child as a permanent active interval.
- **Inherited private context** → Use the host's private-fork boundaries; keep private lookups, payloads and failure details out of public changelogs. An external model may still process the fork's context.

## Migration Plan

- The standalone Pi package is `pi-audit-todo`; its projected entry is `index.ts` and the predecessor remains untouched. Preserve the board keys and `audit.enabled: false` business off-switch. Stop registering `/jev-audit-service`; keep `/jev-audit` as an explicit check of currently due items, without bypassing per-item decisions or forcing execution. `/jev-audit full` reports retirement of JEV full reassessment instead of launching a paid rebuild. No new manual scheduling mode is required.
- Do not install, uninstall, change credentials, edit Pi selections or reuse classifier scores. Document legacy resource filters (`index.ts` remains the maintenance entry), obsolete JEV settings, new time units, migration of commands and how to disable. Preserve old visible advice and recover the ordinary TODO board independently of prior judgments.
- Verify against a disposable main session before activation. For rollback disable maintenance and return to the previous pinned plugin version; do not replay inverse mutations. Already committed TODO updates are ordinary user-visible board history. Do not alter the standalone watchdog or JEV installations during upgrade or rollback.
